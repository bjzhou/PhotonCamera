# U2NetP 主体 mask 与分层深度细化

## 论文与实现边界

参考 Kim et al., [Layered Depth Refinement with Mask Guidance (CVPR 2022)](https://sooyekim.github.io/MaskDepth/)
的分层思想：分别细化 mask `M` 与反向 mask `1-M` 的深度，再按覆盖率合成。
论文使用外部高质量 mask 和训练好的深度补全网络。本实现以
[U2NetP](https://huggingface.co/edgetools/u2netp) 从 RGB 估计显著性 mask，再结合相对视差和焦点深度，
通过 GLES 的局部颜色模型与同层归一化卷积实现边界细化，不复现论文的深度补全网络。

U2NetP 输出显著性，不输出人物类别或实例编号。同一张 mask 可能包含多个显著对象。
焦点位于 mask 内时保护分割主体；焦点移至 mask 外时，仍使用 mask 细化几何，但撤销主体清晰保护，
以实际表面深度驱动双向虚化。相似颜色、分割本身漏掉的细结构和深度严重错误仍可能影响结果。

## TFLite 推理

模型打包在 `app/src/main/assets/u2netp/u2netp.tflite`，无需额外下载或 ONNX Runtime。
`SharedSubjectMaskEstimator` 在专用单线程和 Mutex 内懒加载、推理与释放，使用现有 TFLite
CPU/XNNPACK、4 个线程。资产不压缩，以 `assets.openFd` 映射加载，并严格验证张量类型与形状。

- 输入：从原图选定的整数裁切框一次 Canvas 绘制到 sRGB ARGB_8888 的 320×320 小图，包含 HDR 到显示色域的转换；
  不保持纵横比、不加边框。RGB 除以小图中所有通道的最大字节值，全黑时分母为 1，再执行 ImageNet
  mean/std 归一化，写入 FP32 NHWC `[1,320,320,3]`。
- 输出：单路 fused sigmoid，FP32 `[1,320,320,1]`。校验有限值、范围和动态范围后，
  min/max 归一化为 `SubjectMask`，携带裁切框在原图中的 UV 范围，不经过 8-bit mask 中间图。
- 推理失败或输出不可用时记录错误并保留原图，不退回到由深度猜出的主体 mask。
  协程取消会传播，临时 Bitmap 和 native direct buffers 在 `finally` 释放。

转换脚本为 `scripts/convert_u2netp_to_tflite.py`。它只接受指定 SHA-256 的源图，保持原始权重和
FP32 精度，将 NCHW 改为 NHWC、折叠静态形状计算、保留第一路 fused 输出；图中只有 TFLite
内置算子，无 Select TF Ops。来源、许可、校验值和数值验证记录随资产保存在 `u2netp/`。

## 深度引导的自适应裁切

`DepthSubjectCropPlanner` 只决定 RGB 的输入范围，深度分类结果不会作为最终 mask。
范围完全由原始深度和原图尺寸决定，不依赖点击焦点，也不先使用依赖 mask 的深度极性预处理。
这样重新对焦不会选择另一块背景去重新定义主体，导入相反极性的深度也可以使用同一条处理链。

- 256 桶直方图的 Otsu 分组需有至少 0.12 的均值分离，且类间方差解释至少 85% 的总方差。
  图像边缘带至少 90% 属于同一组时，才把另一组作为候选物体区域；平坦深度、透视渐变和不明确的背景使用全图。
- 候选面积需占 0.5%–45%。使用八邻域连通域移除不足 0.025%（至少 4 个深度像素）的孤立小块，
  所有剩余物体共同确定外接框，不能只保留最大的主体。
- 在原图像素坐标中，每侧保留至少物体外接框长边 25% 或原图短边 3% 的背景余量，另加一个深度像素足迹。
  扩成至少 320 像素的正方形；靠近图像边缘时平移范围。只有两轴最小采样倍率至少 1.25、
  裁切面积小于全图 65% 时才采用裁切，避免低分辨率放大和收益不足的处理。
- U2NetP 输出若在内部裁切边缘的 4 像素带中出现覆盖率至少 0.5，表示候选范围可能截断了主体，
  放弃局部结果，重新对完整原图推理。原图自身的边缘不属于截断证据。不补洞、不延伸或拼接预测出的主体。
  通常执行一次推理，候选被此检查拒绝时执行两次；日志分别记录裁切原因、范围、倍率、规划与推理耗时。

这些条件用于保守地判断裁切是否适用，并不保证每种场景的分割精度都会提高。
多层复杂场景和未被深度分离出的细结构仍需要用真实照片验证。

## 数据与处理链

输入保持 `RelativeDepthMap` 的 `[0, 1]` 视差约定，数值越大越近。全链使用原图归一化坐标。
工作分辨率继续限制在长边 2560，mask 不依赖光圈或照片输出分辨率。
深度正反方向以可靠分割内部的深度中位数作为固定参考，并对非主体区域评分；不再随点击焦点翻转。
缺少可靠分割内部时保持输入视差方向，实际点击仅决定焦点深度。

1. **分层上采样。** 在 U2NetP mask 的 4×4 邻域中，RGB 与空间权重共同决定软覆盖率。
   320×320 纹理只覆盖 `SubjectMask.region`；不先缩回全图 320×320。
   `uMaskBounds` 将局部 texel 中心映射到原图 UV，RGB 引导的采样足迹也按裁切比例缩小。
   裁切外使用虚拟零 mask 网格，继续采样真实深度和 RGB；禁止把 ROI 外全部写成固定深度或重复边缘 mask。
   按原图 UV 独立采样深度纹理，不把 mask texel 索引用到尺寸不同的深度图上。
   可靠主体样本和非主体样本分别归一化深度，
   非主体的焦前、焦后样本分别累计后选择支持较强的一侧，避免相互平均出虚假的焦平面。
2. **RGB 轮廓细化。** 在源 mask 采样足迹对应的 5×5 邻域内，用可靠 mask 内外样本建立
   两个颜色模型。细化步长使用局部 mask 在原图中的 texel 尺寸，并至少覆盖一个工作像素。
   颜色分离度、层内方差和重建残差决定颜色投影对软 mask 的影响。
   仅在两层均有可靠支持的轮廓带内，以同层样本细化深度；非主体样本不得跨越焦平面传播。
   不执行膨胀、闭运算或整图深度模糊。
3. **参与虚化的颜色准备。** 焦点在主体内时，在线性 RGB 中预乘 `1-M`，再执行工作分辨率归约与 mipmap 生成。
   归约使用原图 level 0 的四个子采样点，避免先读取含有主体颜色的原图 mipmap。
   焦点在主体外时，保护覆盖率为 0，所有可见表面都能参与深度驱动的虚化。
4. **虚化采样。** PSF 使用非主体层的深度计算完整光斑半径，采样预乘颜色并按覆盖率归一化。
   主体 mask 不用于缩小边缘光斑。遮挡排序与遮挡强度使用目标像素实际所属层的深度。
5. **合成与高光。** 主体覆盖率控制原图细节保留；焦前失焦物仍可遮挡主体。
   背景高光单独按 `1-M` 裁切。GPU 紧凑高光和 CPU 解析高光均读取同一 mask，
   CPU 额外检查完整光斑支持域，避免绕过主体保护。

## 纹理契约

| 纹理 | 格式与通道 | 使用方式 |
| --- | --- | --- |
| 模型 mask | R16F：R=U2NetP 软 mask，320×320 | `uMaskBounds.xy` 为原图 UV 起点，`.zw` 为范围；全图为 `(0,0,1,1)` |
| 分层深度 | RGBA16F：R=`M*G+(1-M)*B`，G=主体视差，B=非主体视差，A=`M` | 上采样与细化使用独立 framebuffer 目标，禁止原位读写 |
| 非主体颜色 | RGBA16F：RGB=`linearRGB*(1-M)`，A=`1-M` | 预乘后生成 mipmap，PSF 累计颜色与覆盖率 |
| CPU 分类副本 | RGBA8：R=非主体视差，G=`M`，B=0，A=1 | 仅默认风格回读，不能回流到渲染 |

`sampleBokehLayers` 对覆盖率做双线性采样，对视差取所属 texel。
直接对 B 做双线性插值，会在焦前和焦后的交界生成假的清晰线；R 仅表达合成视差，不能用于 CoC。
CPU 高光中心的视差同样按所属 texel 读取，mask 则保留连续覆盖率。
CPU 焦点采样与深度预处理调用 `SubjectMask.sample`，同样先从原图 UV 转到局部 mask；内部裁切边缘
采用零覆盖率延拓，原图边缘采用 clamp。下游 CPU 高光仍读取已经映射到全图工作分辨率的渲染副本。
主体样本不会被硬写成焦点深度；主体清晰保护是 mask 的合成语义。
当 `uProtectSubject=0` 时，细化 pass 保留 R 的合成几何，将可见表面视差写入 B，并将 A 清零。
此后所有 PSF、颜色预乘、高光和合成 pass 都使用这一相同的保护契约。

中间上采样纹理在细化消费后立即释放。新增 pass 沿用 GLES 3.0 framebuffer 路径，
每次 draw 显式设置所有 sampler；关键 pass 检查 GL error，初始化日志包含 GPU、驱动和纹理尺寸上限。

## 验证

- `compileDefaultDebugKotlin`。
- `DepthBokehDepthPreprocessorTest` 验证从主体移到背景时焦点深度改变而场景极性不变。
- `DepthSubjectCropPlannerTest` 覆盖深度反转、横竖构图、图像边缘、多主体、噪声、平坦/渐变深度和低分辨率输入。
- `SubjectMaskTest` 覆盖偏移和非等比例 UV 范围、局部细节、内部零边界与原图 clamp 边界、截断判断。
- ONNX/TFLite 数值验证：黑、白、噪声、渐变与两张已有示例照片共 6 组输入，raw saliency 最大绝对误差
  `5.585e-5`，归一化 mask 最大平均绝对误差 `1.878e-5`。具体记录见资产目录的 `u2netp.json`。
- `:app:testDefaultDebugUnitTest --tests com.hinnka.mycamera.lut.BokehShadersTest`：
  包含新增 shader、现有风格变体的 NDK GLSL 校验；SDK 路径支持从模块目录读取根目录的 `local.properties`。
- 本机 SwiftShader ES 3.0 已验证生产 shader 的编译、链接、RGBA16F 分配、draw、mipmap 与回读，
  覆盖全主体、全背景、孔洞、HDR、焦前/焦后交界、mask 水平错位、背景重新对焦，
  以及深度恒定但 mask 有孔洞的场景；mask 与深度使用不同尺寸。
- 裁切链额外验证居中/偏移/贴原图边缘的局部 mask，裁切外深度有效、重新对焦撤销保护，
  以及局部细孔没有因为回贴到整图低分辨率网格而消失。
