# 基于像素对应点的 LUT 模型

2026-09-28。此次完成算法实现与验证，不进行长时间训练，不替换 App 中现有权重。验证文件位于 `scripts/lut_training/runs/point-pairs-check/`，明确用于流程检查，不能作为已训练好的仿色模型。

## 任务与本地仿色的关系

本地 `LocalImageAnalyzer` 从原图与效果图提取对应颜色，`LutGenerator` 根据这些点插值成 LUT。单张效果图没有已知原图，因此网络负责预测原色对应点，拟合器负责生成三维映射。训练仍采用 `origin.jpg + 手机 LUT = 效果图`，只有效果图输入网络，原图和 LUT 用于监督。

旧结构 `legacy` 有独立逐通道曲线和低秩 LUT 混合系数；新结构 `pixel_pairs` 没有这些输出。新结构直接学习 RGB→RGB 对应关系，允许跨通道、选择性色相和非线性映射。为保持用户指定的普通 sRGB JPG/LUT 工作流，拟合在 sRGB 数值域进行，没有照搬本地算法的 Oklab 转换、PAVA 单调投影或额外后处理。

## 网络及拟合

1. 224×224 效果图经过共享深度可分离 CNN，得到局部与全局特征。
2. 在14×14空间网格上取196个真实效果像素，网络预测对应的原图RGB及置信度。目标RGB直接读取输入，不由网络自由生成。
3. 另一分支为固定7³源RGB网格预测343个目标RGB，覆盖参考图中没有出现的颜色。这是完整三维颜色控制网格，不是曝光、色温、影调或饱和度参数。
4. 控制网格经三线性插值得到映射 A；像素点对按RGB邻域拟合 A 的局部残差，得到33³ LUT。

对预测源颜色 `sᵢ`、观测目标颜色 `tᵢ`、置信度 `cᵢ`：

```text
K(q,s) = exp(-||q-s||² / (2σ²))
densityᵢ = Σⱼ K(sᵢ,sⱼ)
wᵢ(q) = K(q,sᵢ) × cᵢ / densityᵢ
eᵢ = tᵢ - A(sᵢ)
LUT(q) = A(q) + Σᵢ wᵢ(q)eᵢ / (λ + Σᵢ wᵢ(q))
```

默认 σ=0.14、λ=0.1。该闭式解对应局部残差的正则化加权最小二乘问题。密度归一化避免同一种颜色出现大量重复像素后压过其他颜色；λ使缺少观测的颜色保持学习到的控制网格，而不是凭空把这些颜色当作已知对应点。保留原始输出参与监督，导出最终值才限制到0..1。

实现文件：`point_model.py`、`point_fitting.py`。PyTorch与TensorFlow实现同一公式；TFLite包含完整预测与拟合，不需要App另外执行求逆、拟合或颜色空间转换。

## 数据、监督与评估

新模型先把原图缩放到224²，再由原生LUT生成同尺寸效果图。固定对应点从这些对齐图像取样，禁止训练时先渲染320再平均到224，因为非线性LUT与像素平均不交换。JPEG观测增强只作用于输入，干净目标保留。部署使用完整图像的bicubic缩放到224²，模型输入NCHW RGB，范围0..1。

增加四项监督：

- 源颜色点对误差，按源颜色分组平衡权重。
- 343个控制点目标RGB误差。
- 实际原色经拟合LUT后的点对误差。
- 基于源色预测误差与观测误差构造的置信度目标，目标停止梯度；点对误差本身不乘预测置信度，避免网络通过降低置信度逃避监督。

同时保留完整LUT误差、同照片与跨照片渲染误差、同风格一致性、曲率和范围约束。评估增加 `pair_source_mae`，以及移除像素拟合时的 `base_lut_mae/base_render_mae/base_cross_scene_mae`。必须比较拟合分支是否真正改善跨照片表现，不能仅凭输出有变化或训练损失下降判断成功。

新检查点格式为2，记录 `architecture=pixel_pairs`。旧格式1可继续评估、预测或导出，显式 `--architecture legacy` 可训练旧结构；禁止把旧检查点当作新结构恢复。训练命令默认新结构，且要求render_size=224。

## 预算

| 项目 | 数值 |
|---|---:|
| 可训练参数 | 646,537 |
| CNN与投影/预测头估算 MAC | 144.37M |
| 点对距离与残差投影估算 MAC | 42.38M |
| 合计估算 MAC | 186.75M |
| 检查点导出 FP32 TFLite | 3,716,028 字节 |
| 单切片核权重矩阵 | 约0.81 MiB |

MAC不含指数、归一化和插值等操作，不能换算为手机实际时延。拟合按33个网格切片计算，避免单次推理建立完整35937×196权重矩阵；训练反向仍会保留多个切片的中间量。编码器可选CUDA混合精度，点对、控制网格、拟合、损失保持FP32。导出仍限制200万参数与8 MiB文件。

## 实际验证结果

### 真实点对的拟合验证

`audit-pairs` 独立验证拟合器，使用真实原色、效果色及标签LUT控制点，**不包含网络预测误差**。40个留出LUT各使用两张验证照片，一张提取点对，另一张检查迁移：

| RGB MAE | 只有控制网格插值 | 加入真实像素点对 |
|---|---:|---:|
| LUT网格 | 0.008965 | 0.008748 |
| 同照片套图 | 0.008705 | 0.005359 |
| 跨照片套图 | 0.009937 | 0.007730 |

40例中3例的跨照片误差变差；局部点对不保证全域精度都提高。恒等、通道置换和跨通道仿射探针误差均为0；重复每个点对后输出最大变化3.28e-7，验证密度归一化。记录在 `runs/point-pairs-oracle.json`，不是可用模型的质量结论。

### 训练与转换流程

- CPU、MPS对编码器、特征投影、控制点头、像素点头的反向传播均产生非零且有限梯度。
- MPS执行4次优化及736张合成参考观测验证，约49秒，保存/加载格式2检查点成功；旧 `train-srgb` 检查点仍可加载。
- 68个真实及合成输入的FP32导出对照：LUT最大绝对误差2.38e-7，套图最大绝对误差2.98e-7。
- 独立点对头对照最大误差1.19e-7，随机非恒等头对照2.38e-7，防止初始近恒等输出掩盖拟合转换错误。
- TFLite只用内置算子，无Flex、自定义算子或外部求解器。
- 桌面TFLite 2.17 CPU成功执行新图，相对2.21导出环境的固定随机输入最大误差5.96e-8；这不等同于Android真机验证。

仅4次优化的检查点不代表仿色质量。这次没有手机连接，未测新结构的真机耗时，也未把检查文件写入App资源。现有App模型仍为用户先前指定的 `train-srgb/model.tflite`。
